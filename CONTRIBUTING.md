# Contributing

Read PROJECT_RULES.md, AGENTS.md, PROJECT_STATE.json, and the relevant protocol before starting.

Every substantive change uses a PR and states task/change ID, summary, scope, non-goals, change class, tests/checks, evidence or experiment IDs, risks, rollback/disable strategy, relevant ADR, and state updates.

Do not merge because CI is green alone. Critical paths require the review and evidence controls defined by PROJECT_RULES.md.

Do not turn AI output, snippets, README claims, or anecdotes into project facts without verification. Performance/game-boost claims require scoped measurement and preserved raw/negative results.

Never commit secrets, credentials, private user data, or unsupported proprietary material.
